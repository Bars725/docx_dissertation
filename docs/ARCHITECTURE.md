# Архитектура: оформление диссертации в .docx по ГОСТ

## 0. Какой ГОСТ

| Стандарт | Что регулирует | В программе |
|---|---|---|
| ГОСТ 7.32-2017 | Отчёт о НИР: поля 30/15/20/20 мм, TNR ≥12 пт, 1,5 интервала, отступ 1,25 см, номер страницы внизу по центру, структурные элементы прописными по центру | пресет **по умолчанию** `gost-7.32-2017` |
| ГОСТ 2.105-95 | Общие требования к текстовым документам (нумерация разделов, приложения) | учтён в правилах нумерации/приложений |
| ГОСТ Р 7.0.11-2011 | **Диссертация и автореферат**: поля 25/10/20/20 мм, 12–14 пт, 1,5 интервала, номер страницы **вверху** по центру, заголовки глав по центру | пресет `gost-r-7.0.11-2011` |
| ГОСТ Р 7.0.100-2018 | Библиографическая запись (список литературы) | текст записи вводит пользователь; программа нумерует |

Для диссертации обычно требуют ГОСТ Р 7.0.11-2011 и локальные требования совета.
Поэтому все числа живут в профиле (`FormattingProfile`), а не в коде. Их можно
поменять в JSON или извлечь из образца вуза.

### Сценарии

1. **Загрузка образца**: `TemplateParser.extract()` → профиль → JSON в папке профилей → выбирается при создании документа.
2. **Создание документа**: `DocumentBuilder.new(profile)`: A4 и поля, стили, `PAGE` в колонтитуле, пустой колонтитул первой страницы.
3. **Выбор документа**: `DocumentBuilder.open(path)`. Профиль по умолчанию извлекается из самого документа, поэтому новые фрагменты выглядят как уже набранные. Чужие стили не меняются (это покрыто тестом). Можно принудительно привести документ к профилю (`enforce_styles=True`).
4. **Вставка**: тип блока + заголовок + текст → `TextCleaner` → план `[(роль, текст)]` → позиция → абзацы со стилем роли → `renumber()`.

## 2. Ключевые проектные решения

**Всё оформление — в стилях.** Вставленный абзац содержит только `w:pStyle` и
run без `w:rPr`. Тест `test_inserted_runs_have_no_direct_formatting` это проверяет.
Поэтому при повторном открытии в Word оформление держится, стиль меняется
централизованно, а оглавление и навигация работают.

**Роли → стили.** Главы, подглавы и пункты оформляются встроенными
`Heading 1–3`: их понимают оглавление Word, LibreOffice и Google Docs.
Остальные роли (`ГОСТ Основной текст`, `ГОСТ Структурный элемент`,
`ГОСТ Список литературы`, `ГОСТ Приложение`…) — собственные стили с латинским
`styleId` и русским именем. Роль ищется по id **и по имени**, потому что LibreOffice
при пересохранении переименовывает id (`GostBody` → `Style5`).

**Абзацный отступ и 1,5 интервала — не в Normal.** Normal задаёт только шрифт,
кегль и язык. Иначе интервал и отступ «протекают» в таблицы, колонтитулы и подписи.

**Нумерация заголовков текстом, а не списком Word.**

| Вариант | Плюсы | Минусы |
|---|---|---|
| Текстовый префикс `1.2 ` + `renumber()` (**выбран**) | Одинаково выглядит в Word/LO/Google Docs; формат из образца («Глава 1.», «1.», «1») | Если пользователь вставит главу руками прямо в Word, номера обновятся только при следующем сохранении программой |
| Многоуровневый список `numbering.xml`, привязанный к Heading | Word перенумерует сам | python-docx не умеет numbering API; список ломается при копировании между документами и в Google Docs |

Если в образце заголовки пронумерованы списком Word, парсер это видит и
отключает текстовую нумерацию, чтобы номера не задваивались.

**«Умная» позиция вставки.** Глава встаёт перед заключением, списком литературы
и приложениями, а введение — перед первой главой. Записи литературы всегда
дописываются в конец существующего списка. Приложение — в конец документа.
Явные режимы тоже есть: «после элемента» и «в конец раздела».

**Атомарное сохранение.** Документ пишется во временный файл, затем открывается
для проверки, после чего `os.replace`. Перед первой перезаписью делается `.bak.docx`.
Если файл открыт в Word, пользователь получит понятную ошибку, а оригинал не пострадает.

## 4. Самые рискованные места и как они решены

### 4.1 Извлечение параметров из образца (`template_parser.py`)

python-docx возвращает только *локальные* значения
(`paragraph_format.first_line_indent is None`, если отступ задан в стиле), поэтому
эффективное значение вычисляется по цепочке:

```
run.rPr → rStyle (символьный) → pStyle → basedOn … → docDefaults → theme1.xml
p.pPr   → pStyle → basedOn … → docDefaults
```

```python
def _ppr_attr(self, el, tag, attr):                 # template_parser.py
    for ppr in self.resolver.ppr_chain(el):         # прямое → стиль → basedOn → docDefaults
        child = ppr.find(qn(tag))
        if child is not None and child.get(qn(attr)) is not None:
            return child.get(qn(attr))               # атрибут-за-атрибутом: w:ind left
    return None                                      # может быть в стиле, firstLine — прямо
```

* Шрифт кириллицы берётся из слота `w:hAnsi`, а не `w:ascii`. Если там
  `w:hAnsiTheme="minorHAnsi"`, шрифт читается из темы.
* Значения собираются по всем абзацам «основного текста» (длинные, вне таблиц,
  без списков и служебных стилей) и выбираются **взвешенной модой** по длине
  текста, поэтому один криво оформленный абзац не перекосит профиль.
* Межстрочный интервал: `lineRule="auto"` даёт `line/240`; при exact/atLeast
  значение переводится в множитель и округляется до 0,25.
* Разрыв страницы перед заголовком считается найденным, если задан `pageBreakBefore`,
  в предыдущем абзаце есть `<w:br w:type="page"/>` или стоит разрыв раздела.
* Формат номера («Глава {n}. {title}», «{n}.{m}. {title}», «[{n}] ») определяется по тексту заголовков и записей.
* Всё не найденное берётся из ГОСТ и попадает в `extraction_report`. GUI показывает этот отчёт пользователю.

### 4.2 Применение стилей ГОСТ (`style_manager.py`)

```python
rpr = style.element.get_or_add_rPr()
ooxml.set_fonts(rpr, "Times New Roman")   # ascii, hAnsi, cs, eastAsia + удалить *Theme
ooxml.set_size(rpr, 14)                   # sz и szCs
ooxml.set_black_color(rpr)                # удалить themeColor (Heading в Word синие)
pf = style.paragraph_format
pf.line_spacing = 1.5; pf.first_line_indent = Cm(1.25); pf.page_break_before = True
ooxml.get_or_insert(ppr, "w:outlineLvl", PPR_SEQ).set(qn("w:val"), "0")  # в оглавление
```

`get_or_insert` вставляет элемент **в порядке схемы** (`PPR_SEQ`/`RPR_SEQ`).
Тест `test_schema_order_in_ppr` проверяет порядок во всех стилях.

### 4.3 Вставка сырого текста и раздробленные runs (`runs.py`, `document_builder.py`)

* **Новые абзацы** создаются как `<w:p><w:pPr><w:pStyle/></w:pPr><w:r><w:t/></w:r></w:p>`
  и ставятся через `addnext/addprevious` относительно якоря (абзаца или таблицы) либо
  через `add_paragraph()` перед финальным `w:sectPr`.
* **Замена текста** (нумерация, плейсхолдеры `{{TITLE}}`) работает на уровне абзаца.
  Строка склеивается из всех `w:t` (включая гиперссылки и вставки правок),
  совпадения ищутся в склейке и проецируются обратно на `w:t`. Замена получает
  форматирование run, где начинается совпадение. Табуляции, разрывы и `fldChar`
  — барьеры, через которые совпадение не проходит, поэтому поля не ломаются.
  Удалённый текст (`w:del`) и вложенные надписи не затрагиваются.
* **Полная замена текста** (`set_paragraph_text`) сохраняет `pPr`, закладки
  (якоря оглавления `_Toc…`) и диапазоны комментариев.
* Обход частей документа (`iter_all_paragraph_elements`) охватывает тело,
  вложенные таблицы, `w:sdt` и все колонтитулы всех секций без дублей связанных.

### 4.4 «Живые» ссылки на литературу

```
список:  <w:bookmarkStart w:name="_GostRef_R3"/><w:r><w:t>3</w:t></w:r><w:bookmarkEnd/>. Иванов…
текст:   [ <fldChar begin/> REF _GostRef_R3 \h <fldChar separate/> 3 <fldChar end/> , с. 15]
```

Ключ записи (R3) не меняется при сортировке, меняется только номер внутри закладки.
Word по F9 сам подставит номер из закладки. Программа при любом изменении списка
пересчитывает номера и кэш всех полей `REF`, поэтому документ верен и без F9
(и в LibreOffice: это проверено пересохранением). Новый ключ всегда больше всех
занятых, включая ключи «осиротевших» ссылок, чтобы ссылка на удалённый источник
не прицепилась к новому.

## 6. Рекомендации по стабильности (известные проблемы python-docx)

1. **Letter вместо A4.** Встроенный шаблон python-docx — 215,9×279,4 мм. Всегда задавать размер явно (`apply_page_setup`).
2. **`font.name` пишет только `ascii/hAnsi`.** Кириллица в `cs/eastAsia` и ссылки `*Theme` остаются, и Word показывает Calibri (особенно в колонтитулах). Используйте `ooxml.set_fonts`.
3. **Цвет темы.** Heading в Word синие через `w:themeColor`, поэтому `font.color.rgb` мало, нужно удалять атрибуты темы.
4. **Порядок элементов схемы.** Ручное `append()` в `pPr/rPr` даёт файл, который Word «восстанавливает» или открывает с ошибкой. Только `get_or_insert`.
5. **Раздробленные runs.** Никогда не ищите текст в `run.text`. Ищите в склейке абзаца (`runs.replace_text`).
6. **`paragraph.text = ...` и `paragraph.clear()`** удаляют гиперссылки, поля, закладки оглавления. Используйте `set_paragraph_text`.
7. **`doc.paragraphs` не видит** абзацы в таблицах, `w:sdt`, надписях и колонтитулах. Обход через `iter_all_paragraph_elements`.
8. **Латентные стили.** `doc.styles['Heading 2']` может бросить `KeyError` в файле из Word (стиль только в `latentStyles`). Его нужно создать через `add_style('Heading 2')`, python-docx сам сопоставит встроенное имя.
9. **Локализованные имена.** В русском Word стиль хранится как `heading 1` (имя UI — «Заголовок 1»). Ищите по `styleId`/внутреннему имени, а не по отображаемому.
10. **styleId меняются** (LibreOffice: `Style5`). Роли ищутся по id и имени.
11. **Google Docs** не хранит пользовательских стилей: при импорте/экспорте оформление переходит в прямое форматирование, а Heading остаются. Парсер использует взвешенную моду по прямому форматированию, а при продолжении работы недостающие стили ГОСТ создаются заново.
12. **Поля не вычисляются.** `PAGE` и будущий `TOC` получают кэш-значение. Word/LO пересчитывают их при открытии или печати; для оглавления нужно F9 или `w:updateFields` в settings.
13. **Разрыв страницы:** предпочитайте `pageBreakBefore` в стиле вместо `<w:br w:type="page"/>` (иначе пустые страницы при правке).
14. **Нумерация списками** (`numPr`) у Heading в образце плюс текстовые номера дают двойную нумерацию. Парсер это распознаёт.
15. **Файл открыт в Word** (Windows): `PermissionError` при сохранении. Атомарная запись через временный файл и понятное сообщение.
16. **Не меняйте чужое.** При открытии документа по умолчанию только *добавляются* недостающие стили. Тест сравнивает XML стиля Heading 1 до и после.
